# Cluster Compatibility & Setup Overview

Gefyra is engineered to run against **any standard Kubernetes cluster (v1.24+)**, whether running locally on your laptop or hosted in enterprise cloud environments.

Because Gefyra operates purely at the container network and user-space operator level, it requires **no proprietary kernel modules** or invasive cluster-wide service meshes (like Istio or Linkerd).

---

## Compatibility Matrix

### Local Development Clusters

| Platform | Driver / Runtime | Status | Key Characteristics |
| :--- | :--- | :---: | :--- |
| **[k3d](/en/cluster-guides/local-clusters/k3d)** | Docker / Podman | **Recommended** | Blazingly fast startup; automated port exposure via Docker bridge network. |
| **[kind](/en/cluster-guides/local-clusters/kind)** | Docker / Podman | **Full** | Standard CNCF conformance engine; NodePort mapping via `extraPortMappings`. |
| **[minikube](/en/cluster-guides/local-clusters/minikube)** | Docker, Hyperkit, KVM | **Full** | Classic local cluster; requires `minikube ip` or `minikube service` for endpoint reachability. |
| **[Colima](/en/cluster-guides/local-clusters/colima)** | QEMU / Lima (macOS) | **Full** | Lightweight, Docker Desktop-free container runtime with native Kubernetes. |
| **[Docker Desktop](/en/cluster-guides/local-clusters/docker-desktop)** | Virtual Machine | **Full** | Built-in single-node Kubernetes; supports native Docker Desktop Extension. |

### Managed Cloud Kubernetes Providers

| Cloud Provider | Service | Status | Connection Method |
| :--- | :--- | :---: | :--- |
| **[Amazon Web Services](/en/cluster-guides/remote-clouds/eks)** | Elastic Kubernetes Service (EKS) | **Full** | NLB (Network Load Balancer) or NodePort with Security Group opening on UDP 31820. |
| **[Google Cloud Platform](/en/cluster-guides/remote-clouds/gke)** | Google Kubernetes Engine (GKE) | **Full** | Standard or Autopilot with Cloud Firewall rule allowing UDP 31820. |

| **Microsoft Azure** | Azure Kubernetes Service (AKS) | **Full** | Azure Public IP LoadBalancer on port 31820. |
| **Self-Hosted / On-Premise** | RKE2, kubeadm, Talos | **Full** | Standard NodePort or MetalLB BGP configuration. |

## Network Prerequisites: The Stowaway WireGuard Port

When Gefyra installs its operator (`gefyra up` or `gefyra install`), it deploys the **Stowaway** gateway component. Stowaway establishes the encrypted WireGuard link with local developer machines.

- **Protocol:** `UDP`
- **Default Port:** `31820`
- **Service Type:** `NodePort` (default for local clusters) or `LoadBalancer` (common for cloud providers)

```bash
# Example: Install Gefyra with LoadBalancer service type for Cloud EKS/GKE
gefyra install --service-type LoadBalancer
```

If your cluster sits behind a corporate firewall or cloud security group (e.g., AWS Security Group or GCP VPC Firewall), ensure that inbound UDP traffic on port `31820` is permitted to worker nodes.

## Choosing the Right Cluster for Your Workflow

::card-group
  :::card
  ---
  title: Solo Local Fast-Feedback
  icon: i-lucide-laptop
  ---
  Use **k3d** or **kind**. Both spin up in seconds and allow you to test Gefyra bridges offline without an active internet connection.
  :::

  :::card
  ---
  title: Team Shared Staging
  icon: i-lucide-users
  ---
  Use a shared **AWS EKS** or **GCP GKE** staging cluster. Deploy Gefyra once with an external LoadBalancer service, and issue isolated client credentials to team members.
  :::
::
