# Stowaway placement, pod labels, and startup probe

The operator creates the stowaway StatefulSet at runtime. Configure its pod template through installation options rather than editing a running pod. These settings apply to stowaway only. Operator and operator-webhook placement can be customized in their generated Deployment manifests.

| Installation flag / Python option | Type | Default |
| --- | --- | --- |
| `--stowaway-node-selector` / `stowaway_node_selector` | String-to-string map | `{}` |
| `--stowaway-tolerations` / `stowaway_tolerations` | List of Kubernetes toleration objects | `[]` |
| `--stowaway-pod-labels` / `stowaway_pod_labels` | String-to-string map | `{}` |
| `--stowaway-startup-probe-failure-threshold` / `stowaway_startup_probe_failure_threshold` | Positive integer | `3` |

CLI map/list values are JSON. Python callers pass dictionaries/lists directly to `GefyraInstallOptions` or `gefyra.api.install`. Invalid inputs are rejected during installation and again when the operator reads its environment.

## Example

Generate installation YAML without applying it:

```shell
gefyra install \
  --stowaway-node-selector '{"example.com/node-pool":"gefyra"}' \
  --stowaway-tolerations '[{"key":"dedicated","operator":"Equal","value":"gefyra","effect":"NoSchedule"}]' \
  --stowaway-pod-labels '{"example.com/workload":"gefyra-stowaway"}' \
  --stowaway-startup-probe-failure-threshold 60
```

The nodes must already have the selected labels and, where applicable, matching taints. All `nodeSelector` entries must match. A node-pool label restricts placement to that pool; a unique label, such as the actual `kubernetes.io/hostname` value, restricts placement to one node. A toleration permits placement on tainted nodes but does not select those nodes.

Tolerations accept `key`, `operator` (`Equal` or `Exists`), `value`, `effect`, and `tolerationSeconds`. `operator` defaults to `Equal`. An empty key requires `Exists`, which also requires an empty value. `tolerationSeconds` is an integer applicable only to `NoExecute`; negative values follow Kubernetes' immediate-eviction semantics. Unknown fields are rejected.

Pod labels are merged with Gefyra's built-in labels in `spec.template.metadata.labels`. Conflicting values for `gefyra.dev/app`, `gefyra.dev/role`, or `gefyra.dev/provider` are rejected; repeating the same value is allowed. Supplemental labels do not change StatefulSet or Service selectors. Pod annotations are not configurable through this option.

The startup probe retains its existing endpoint, one-second interval, and five-second initial delay. A failure threshold of 60 permits roughly 60 seconds of startup probing after that delay. Readiness and liveness probe settings remain unchanged. The threshold must fit Kubernetes' positive int32 range.

## Operator environment

The generated operator and webhook Deployments carry the following configuration. Administrators managing manifests separately can set the same environment variables:

| Environment variable | Encoding | Default |
| --- | --- | --- |
| `GEFYRA_STOWAWAY_NODE_SELECTOR` | JSON object | `{}` |
| `GEFYRA_STOWAWAY_TOLERATIONS` | JSON array | `[]` |
| `GEFYRA_STOWAWAY_POD_LABELS` | JSON object | `{}` |
| `GEFYRA_STOWAWAY_STARTUP_PROBE_FAILURE_THRESHOLD` | Integer string | `3` |

`CONNECTION_PROVIDER_STARTUP_TIMEOUT` is a separate operator readiness-wait limit (default 180 retries, with a one-second retry delay). Large probe thresholds may require raising this limit on the operator as well.

## Updates and resets

Generate and apply updated Deployment manifests through your installation management process. The operator reads environment settings on startup. `gefyra install --apply` is an installation path that does not update existing Deployments; use your normal manifest update process for an existing installation.

On startup, the operator reconciles stowaway's image, node selector, tolerations, supplemental pod labels, and startup probe failure threshold even when the image has not changed. It patches only these managed fields, preserving the StatefulSet identity, PVC templates, selectors, other container settings, and unrelated metadata. Repeated reconciliation without changes does not patch the StatefulSet. The operator waits for the StatefulSet controller to observe the updated generation and for the pod to match the updated revision before reporting stowaway ready.

Explicit `{}` removes previous node-selector constraints. Explicit `[]` clears configured tolerations. Removing supplemental labels clears keys previously managed by this option and preserves unrelated labels added by other systems. The operator records owned label keys in the StatefulSet metadata annotation `gefyra.dev/stowaway-pod-label-keys`; do not edit this bookkeeping annotation. It is not a configurable pod annotation.

Changing a pod-template setting rolls the single stowaway pod and temporarily interrupts active connections. Moving between nodes also requires compatible PVC topology, storage attachment, networking, and WireGuard support on the destination. An unmatched selector leaves the new pod Pending; it does not fall back to other nodes.
